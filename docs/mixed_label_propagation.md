# Deep Mixed Label Propagation

This project implements the deep method from:

> Furen Zhuang and Pierre Moulin, "Deep Semi-supervised Metric Learning with
> Mixed Label Propagation", CVPR 2023.

The paper is available locally at
[papers/Deep_Semi-Supervised_Metric_Learning_with_Mixed_Label_Propagation.pdf](../papers/Deep_Semi-Supervised_Metric_Learning_with_Mixed_Label_Propagation.pdf).

The implementation is split into two independent components:

1. `mixed_label_propagation` is a reusable semi-supervised method. It generates
   pseudo-labels and confidence weights from the current model embeddings and
   can be combined with any existing metric-learning loss.
2. `MixedLabelPropagationProxyLoss` is the paper's confidence-weighted proxy
   loss, implemented through `BaseMetricLossFunction`. It can also consume
   pseudo-labels generated by another SSL method.

Using both components together reproduces the algorithmic structure of the
paper's deep method.

## Motivation

Ordinary label propagation assumes that nearby samples should receive similar
labels. This is useful for finding positive pairs along a data manifold, but it
also makes close samples difficult to identify as negatives.

The paper addresses this limitation in two stages:

1. It estimates whether an edge connects dissimilar samples by approximating
   the label propagation result after removing that edge.
2. It performs mixed label propagation using both similarity edges and the
   newly estimated dissimilarity edges.

The resulting pseudo-labels identify both far-apart positives and close hard
negatives. During deep training, these pseudo-labels and their confidence
weights supervise a proxy-based metric loss.

## Paper-To-Code Pipeline

### 1. Extract Deep Features

Paper equation (14) extracts L2-normalized features:

```text
v_i = g_phi(x_i)
```

The project extracts embeddings from the current `DinoWrapper` model using
`extract_embeddings`. The embeddings returned by the model are L2-normalized.
When `update_mode` is `every_epoch`, this step is repeated using the latest
model, matching the paper's deep iterative training procedure.

Implementation:

- `MixedLabelPropagationPseudoLabeler.generate_pseudo_labels`
- `extract_embeddings`

### 2. Construct The Sparse Similarity Graph

Paper equation (15) defines the directed affinity:

```text
A_ij = max(v_i^T v_j, 0)^gamma
```

when `i` is among the `k` nearest neighbors of `j`. The symmetric similarity
matrix is:

```text
W = A + A^T
```

`make_mixed_label_affinity` uses FAISS inner-product search on normalized
embeddings. On normalized vectors, ranking by inner product is equivalent to
ranking by Euclidean distance. One implementation difference is computational
rather than mathematical: `IndexFlatIP` performs exact exhaustive search,
whereas the paper discusses scalable FAISS indexing.

Configuration mapping:

| Paper symbol | Configuration key | Default |
|---|---|---:|
| `k` | `method_params.n_neighbors` | `50` |
| `gamma` | `method_params.gamma` | `3` |

### 3. Run Initial Label Propagation

The paper replaces the scalar label-fitting weight with a diagonal matrix
whose entries are `mu` for labeled nodes and zero for unlabeled nodes
(equation 16). Consequently, unlabeled propagated labels are determined only
by graph smoothness.

The implementation builds:

```text
L = D - W
U_ii = mu for labeled nodes, otherwise 0
Y = one-hot labels for labeled nodes, otherwise 0
```

and solves:

```text
(L + U) F = U Y
```

The shared sparse-system helper calls SciPy's `cg` independently for every
class. Setting `linear_solver` to `cholmod` instead factors the same matrix once
and solves all class columns together.

For mixed LP, the initial and final matrices share the affinity graph's sparse
pattern. The CHOLMOD backend therefore reuses the first factor's symbolic
analysis and fill-reducing permutation for the second numeric factorization
(`factorize` with scikit-sparse 0.5, `cholesky_inplace` with 0.4). If the
canonical CSC patterns do not match exactly, it safely performs a fresh
analysis.

Configuration mapping:

| Paper symbol | Configuration key | Default |
|---|---|---:|
| `mu` | `method_params.mu` | `1/99` |
| solver tolerance | `method_params.cg_rtol` | `1e-5` |
| solver iteration limit | `method_params.cg_max_iter` | `1000` |

### 4. Estimate Hard-Negative Edges

The central contribution of the paper is estimating what labels two connected
samples would receive if their connecting edge were removed.

For each undirected graph edge `(i, j)`, equation (20) computes:

```text
Z_tilde_i,j = softmax(lambda * (D_ii F_i - w_ij F_j))
Z_tilde_j,i = softmax(lambda * (D_jj F_j - w_ij F_i))
```

These are approximations of the propagated class probabilities after excluding
the opposite endpoint from each node's first-order neighborhood.
The implementation follows equation (20) and uses the unnormalized numerator
`D_ii F_i - w_ij F_j`; it does not apply equation (19)'s scalar denominator
before the softmax.

Equation (21) defines entropy confidence:

```text
omega(p) = 1 - H(p) / log(C)
```

Equation (22) then gives the dissimilarity edge weight:

```text
p_dis(i,j) = 1 - Z_tilde_i,j^T Z_tilde_j,i
W_dis(i,j) = omega(Z_tilde_i,j) * omega(Z_tilde_j,i) * p_dis(i,j)
```

An edge receives a high dissimilarity weight only when the two edge-removed
predictions confidently disagree.

Implementation:

- `make_dissimilarity_affinity`
- `stable_softmax`
- `entropy_confidence`

Configuration mapping:

| Paper symbol | Configuration key | Default |
|---|---|---:|
| `lambda` | `method_params.temperature` | `4` |
| implementation detail | `method_params.edge_batch_size` | `65536` |

`edge_batch_size` only limits temporary edge-by-class tensors. It does not
change the equations and keeps memory near the paper's sparse
`O(Nk + NC)` formulation.

### 5. Run Mixed Label Propagation

Paper equations (23) and (24) add a dissimilarity objective:

```text
D(G) = sum_c sum_i,j W_dis(i,j) * (G_ic + G_jc)^2
```

Similarity edges encourage equal labels through the ordinary graph Laplacian.
Dissimilarity edges penalize assigning large values for the same class to both
edge endpoints.

For symmetric `W_dis`, the dissimilarity term is represented by the signless
graph Laplacian:

```text
Q_dis = D_dis + W_dis
```

The implementation solves the stationary linear system:

```text
(L + U + 2 * beta * Q_dis) G = U Y
```

using the same SciPy-CG/CHOLMOD dispatcher as the initial solve and IS-CEN. The
factor `2` follows from differentiating the paper's directed double-sum form of
equation (24).

Following the paper, every row is normalized exactly as:

```text
G_tilde_i = G_i / ||G_i||_1
```

No clipping or softmax fallback is applied. A zero-L1-norm row cannot be
normalized under the published equation and therefore raises an error. The
pseudo-label is the highest-probability class, and its training confidence is
calculated with equation (21). If an exact L1-normalized row contains negative
values, equation (21) is undefined; the implementation reports that condition
instead of altering the row.

Configuration mapping:

| Paper symbol | Configuration key | Default |
|---|---|---:|
| `beta` | `method_params.beta` | `1` |

Implementation:

- `mixed_label_propagation`
- `solve_sparse_label_system`
- `normalize_mixed_label_rows`

### 6. Train The Deep Metric Model

The paper's equations (26)-(29) maintain one L2-normalized proxy `p_c` per
class. For sample embedding `z_i`, pseudo-label `y_hat_i`, confidence `omega_i`,
scale `alpha`, and margin-like offset `b`, the per-sample objective is:

```text
L_pos(i) = log(1 + exp(-alpha * (z_i^T p_y_hat_i - b)))

L_neg(i) = sum_(c != y_hat_i)
           log(1 + exp(alpha * (z_i^T p_c + b)))

L_i = omega_i * (L_pos(i) + L_neg(i))

L = (1 / C) * sum_i L_i
```

`MixedLabelPropagationProxyLoss` implements this objective through
`BaseMetricLossFunction`. Proxies and embeddings are normalized before their
similarities are calculated.

Configuration mapping:

| Paper symbol | Loss parameter | Default |
|---|---|---:|
| `alpha` | `loss.MixedLabelPropagationProxyLoss.alpha` | `32` |
| `b` | `loss.MixedLabelPropagationProxyLoss.b` | `0.1` |

The loss owns trainable proxies, so it is treated as a classification-style
metric loss and uses the project's classifier optimizer.

## Confidence Handling

Every accepted pseudo-label retains the entropy confidence produced by its SSL
method. `RelabeledSubset` returns this confidence as the optional third batch
item.

- True labeled samples receive confidence `1`.
- Mixed-label-propagation pseudo-labels receive equation (21)'s entropy
  confidence.
- If an SSL method does not supply confidence, its pseudo-labels receive
  confidence `1`.
- Existing losses ignore confidence and continue to receive only embeddings and
  labels.
- `MixedLabelPropagationProxyLoss` consumes confidence as a per-sample weight.

This keeps the SSL method reusable with other losses while allowing the full
paper method to use confidence-weighted optimization.

## Deep Training Schedule

The paper first fine-tunes for five epochs using only labeled samples and then
regenerates mixed-propagation labels in every training epoch.

The provided SSL configuration follows that schedule:

```json
{
  "method": "mixed_label_propagation",
  "update_mode": "every_epoch",
  "warmup_epochs": 5
}
```

At runtime:

1. For the complete paper method, warmup trains only on true labeled samples
   with the same `MixedLabelPropagationProxyLoss` module and optimizer used
   later. Thus both proxy values and optimizer moments carry into propagation.
2. The current model embeds the labeled and unlabeled training pool.
3. Mixed label propagation generates pseudo-labels and confidence.
4. Low-confidence predictions may be removed using `confidence_threshold`.
5. The model trains on true labels plus accepted pseudo-labels using the main
   `loss` and `miner`.
6. With `update_mode="every_epoch"`, steps 2-5 repeat next epoch.

The method is transductive over the configured training pool: pseudo-labels are
generated for the unlabeled samples included in the current SSL split, not for
arbitrary unseen inputs.

## Running The Method

Use only mixed label propagation with another metric loss:

```powershell
.\.venv\Scripts\python.exe main.py `
  --experiment-config configs/experiments/mixed_label_propagation_cifar10.json `
  --loss MultiSimilarityLoss `
  --miner MultiSimilarityMiner
```

Use the complete deep method from the paper:

```powershell
.\.venv\Scripts\python.exe main.py `
  --experiment-config configs/experiments/mixed_label_propagation_cifar10.json
```

To adapt the complete method to another experiment configuration, ensure these
three values are set:

```json
{
  "mode": "ssl",
  "ssl_config": "configs/ssl_mixed_label_propagation.json",
  "loss": "MixedLabelPropagationProxyLoss",
  "miner": "no_miner"
}
```

Warmup never runs propagation itself. For the complete proxy-loss method,
`warmup_loss` must name `MixedLabelPropagationProxyLoss` with `no_miner`; the
runtime aliases the already-created main criterion and optimizer rather than
constructing cold replacement proxies. A propagation-only variant whose main
loss is not the paper proxy may still use the generic warmup keys.

```json
{
  "warmup_loss": "TripletMarginLoss",
  "warmup_miner": "TripletMarginMiner",
  "warmup_loss_params": {
    "margin": 0.2
  },
  "warmup_miner_params": {
    "margin": 0.2
  }
}
```

For classification/proxy-style warmup losses, set `warmup_miner` to `"no_miner"`.

## Configuration Reference

The reusable SSL configuration is
`configs/ssl_mixed_label_propagation.json`.

| Key | Meaning |
|---|---|
| `update_mode` | Shared SSL rebuild cadence. `every_epoch` regenerates graph labels using the latest model each epoch; `every_n_epochs` uses `update_interval_epochs`; `once` reuses one generation. |
| `update_interval_epochs` | Positive interval for `update_mode="every_n_epochs"`. |
| `warmup_epochs` | Number of labeled-only epochs before pseudo-labeling begins. |
| `label_sampling_mode` | Controls how true labeled samples are selected. |
| `labeled_per_class` | Fixed labeled count per class for `per_class_min`; the paper uses five. |
| `confidence_threshold` | Drops pseudo-labels below this confidence before training. |
| `pseudo_label_diagnostics_mode` | `save` writes pseudo-label diagnostics, `log` only logs summaries, and `off` skips diagnostics. |
| `max_unlabeled_samples` | Optional cap on the transductive unlabeled pool. |
| `embedding_batch_size` | Batch size used while extracting graph features. |
| `embedding_num_workers` | DataLoader workers used while extracting graph features. |
| `method_params.n_neighbors` | Number of graph neighbors, paper symbol `k`. |
| `method_params.gamma` | Positive affinity exponent. |
| `method_params.temperature` | Edge-removal probability temperature, paper symbol `lambda`. |
| `method_params.beta` | Dissimilarity objective weight. |
| `method_params.mu` | Label-fitting weight on labeled graph nodes. |
| `method_params.cg_rtol` | Relative conjugate-gradient convergence tolerance. |
| `method_params.cg_max_iter` | Maximum conjugate-gradient iterations per class. |
| `method_params.linear_solver` | `cg` (default, SciPy per class) or `cholmod` (one sparse factorization for all classes). |
| `method_params.edge_batch_size` | Maximum number of graph edges processed together when estimating dissimilarity. |

The proxy-loss parameters `alpha` and `b` use defaults from the paper. They can
be tuned through the existing component HPO keys
`loss.MixedLabelPropagationProxyLoss.alpha` and
`loss.MixedLabelPropagationProxyLoss.b`.

## Relationship To The Paper's Experiments

The algorithmic method follows paper equations (14)-(29), but the provided
experiment configuration is adapted to this repository rather than intended as
an exact reproduction of the published numbers.

| Paper setup | This project |
|---|---|
| BN-Inception backbone | DINOv2 through `DinoWrapper` |
| 64-dimensional embeddings | Combined example uses `feat_dim=64` |
| Five labeled samples per class | Default MLP SSL config uses `labeled_per_class=5` |
| Five labeled-only warmup epochs | Default MLP SSL config uses `warmup_epochs=5` |
| Regenerate mixed LP every epoch | Default MLP SSL config uses `update_mode="every_epoch"` |
| `beta=1`, `gamma=3`, `alpha=32`, `lambda=4`, `b=0.1`, `mu=1/99`, `k=50` | Same defaults |
| AdamW and learning rate `1e-4` | Same optimizer and learning rate in the combined example; no optimizer regularization is configured |
| NMI, Recall@k, Precision@k | Repository currently selects/reports Precision@1 and MAP@R |
| Paper-specific class-disjoint CBIR split | Repository dataset protocols and validation configuration |

Additional implementation details not specified by the paper are exposed
explicitly: exact FAISS search, conjugate-gradient tolerances, edge batching,
and optional confidence filtering.

On Windows, the effective training/evaluation `num_workers` and SSL
`embedding_num_workers` are automatically set to `0`. Windows `spawn` can fail
while serializing the large nested CIFAR subsets used by these experiments.
The configured worker counts remain unchanged and are used normally on other
platforms.

## Practical Considerations

- Mixed label propagation is substantially more expensive than majority-vote
  k-NN because it performs two sparse linear solves per class and estimates
  dissimilarity for every graph edge.
- Runtime grows approximately with the number of samples, graph neighbors, and
  classes. Use `max_unlabeled_samples` for initial experiments on large
  datasets.
- `temperature` is important. The paper's ablation reports greater sensitivity
  to `lambda` than to `beta`.
- A disconnected graph component without a labeled node has no direct class
  supervision and can make the paper's unregularized linear system singular.
- `confidence_threshold=0` preserves all pseudo-labels and lets the paper loss
  weight them continuously. Raising the threshold additionally performs hard
  rejection before training.
- The paper-specific proxy loss does not use a miner. Select `--miner no_miner`.
