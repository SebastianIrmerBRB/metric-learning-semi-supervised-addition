# Datasets, Splits, And Label Budgets

The upstream project delegates dataset loading to `pytorch_metric_learning`,
uses provider train/test splits, and creates one class-disjoint 80/20
train/validation split from the provider train split. This fork adds local
dataset wrappers, CIFAR protocols, validation modes, cross-validation modes,
long-tail transforms, and label-budget support.

Primary files:

- [`utils/`](../../utils)
- [`utils/local_datasets.py`](../../utils/local_datasets.py)
- [`training/semi_supervised.py`](../../training/semi_supervised.py)
- [`class_distribution_report.py`](../../class_distribution_report.py)

## Dataset Set Changed

Upstream supports:

- `Cars196`
- `CUB`
- `INaturalist2018`
- `StanfordOnlineProducts`

This fork's active `DATASETS` list is:

- `Cars196`
- `CUB`
- `DeepFashionInShop`
- `Food101`
- `FGVCAircraft`
- `FGVCFungi`
- `CIFAR100`
- `iNat`
- `iNat2018`
- `iNat2019`
- `iNat2021Mini`
- `StanfordDogs`

`iNat` (also accepted as `SemiINaturalist2021`) is Semi-iNaturalist 2021.
`iNat2018` (also accepted as `INaturalist2018`) uses the upstream metric-learning
split with a local streaming downloader that stores only 224x224 JPEGs.
`iNat2019` (also accepted as `INaturalist2019`) pools the official 265,213
training and 3,030 validation images and follows the Hierarchical Proxy-Based
Loss metric-learning protocol: category ids 0--655 (656 species in 48 genera)
form the development pool and ids 656--1009 (354 species in 24 genera) form the
genus- and class-disjoint final test set. Its downloader streams the 74 GB
archive and retains only atomic 224x224 JPEGs.
`iNat2021Mini` (also accepted as `MiniINaturalist2021` and `iNat2021`) uses all
500,000 official mini-iNaturalist-2021 images and the exact class split released
with Contextual Similarity Optimization. The released manifests contain 5,003
development and 4,997 held-out species (250,150/249,850 images), despite the
paper's rounded 5,000/5,000 description. Its downloader streams the source and
retains only 224x224 JPEGs plus compact metadata.
`StanfordDogs` uses a fixed 60%/40% breed-disjoint development/test split and
the same 224x224 streaming storage strategy.
`FGVCFungi` (also accepted as `Fungi`) is the 2018 FGVCx Fungi challenge. Its
9,758 test images were never labeled, so the loader pools the 85,578 training
and 4,182 validation images and applies Meta-Dataset's canonical class
partition. The image archive's non-contiguous
`images/<taxon id>_<species>/` directory ids are first mapped through the
small official annotation archive and normalized to Meta-Dataset category ids.
The 994 meta-training and 200 meta-validation species are pooled into a
1,194-class development set for cross-validation; the 200 meta-test species
remain the fixed, class-disjoint final test set.
CIFAR-100 is provided by a local wrapper in `utils/local_datasets.py` so it
exposes the same `split` and `labels` shape expected by the rest of the
metric-learning pipeline.

`utils/local_datasets.py` also adds:

- the disk-efficient iNaturalist 2018 downloader;
- the disk-efficient, class-disjoint iNaturalist 2019 loader and downloader;
- the disk-efficient mini-iNaturalist-2021 loader with the published retrieval split;
- the class-disjoint Stanford Dogs loader and downloader;
- the class-disjoint FGVCx Fungi 2018 loader and downloader;
- `RecursiveUnlabeledImageDataset` for external unlabeled image trees;
- a `StanfordOnlineProducts` override that disables download/remove behavior
  where needed by local runs.

## Dataset Protocols

Upstream always preserves the provider train/test boundary.

This fork introduces `dataset_protocol`:

| Protocol | Behavior |
|---|---|
| `official` | Preserve provider train/test splits. |
| `cifar_balanced_fraction` | Combine CIFAR train/test, then create balanced sample-disjoint development and final-test subsets. |
| `cifar10_unseen_classes` | Combine CIFAR-10 train/test, use classes `0-7` for development and classes `8-9` for final test. |
| `cifar100_unseen_classes` | Legacy CIFAR-100 contiguous fine-class split, classes `0-49` development and `50-99` test. |
| `cifar100_fine_class_disjoint` | Fixed 60/40 fine-class split with every superclass represented on both sides. |
| `cifar100_superclass_disjoint` | Fixed split by complete CIFAR-100 superclasses. |

For custom CIFAR protocols, official train and test images are pooled first.
This is a deliberate deviation: the final test boundary is generated by the
protocol rather than by the CIFAR provider.

## Long-Tail CIFAR

The fork adds `cifar_imbalance_factor` for CIFAR datasets. When set, the
development pool is downsampled by class to create a long-tailed distribution.

This behavior is adapted from `richardaecn/class-balanced-loss` and is
attributed in [`THIRD_PARTY_NOTICES.md`](../../THIRD_PARTY_NOTICES.md).

## Validation Modes

Upstream always evaluates on all classes reserved by the initial 80/20 class
holdout.

This fork adds `val_mode`:

| Mode | Behavior |
|---|---|
| `all` | Keep the full validation split. |
| `match_train` | Downsample validation to roughly match the labeled/fractioned training size and class count. |
| `split_after_apportion` | Select the label budget first, then carve a stratified validation split from the apportioned labeled data. |

`split_after_apportion` is especially important for low label budgets because
an earlier class holdout can otherwise remove too many labels before support
selection.

## Cross-Validation Splitters

Upstream has no cross-validation. This fork supports CV over the development
pool:

- sample-level `kfold`;
- class-grouped `group_kfold`;
- sample-level `stratified_kfold`;
- class-grouped `stratified_group_kfold`;
- CIFAR-100 `superclass_balanced_group_kfold`.

Grouped modes keep all samples from a class in the same fold. When SSL is used,
validation-class samples are excluded from pseudo-label candidates for grouped
modes.

## Label-Budget Selection

Upstream trains on all samples in the training split.

This fork can first select a labeled support subset and treat the remaining
training samples as unlabeled candidates. The same machinery is used for
supervised label-budget baselines and SSL runs.

Supported `label_sampling_mode` values:

| Mode | Behavior |
|---|---|
| `global_budget` | Balanced round-robin selection up to `floor(labeled_fraction * train_size)`. |
| `class_subset` | Select a fraction of classes and label all samples from those classes. |
| `class_subset_k_shot` | Select a fraction of classes and label up to `labeled_per_class` images per selected class. |
| `per_class_min` | Keep at least one labeled image per class, or `labeled_per_class` if set. |
| `per_class_imbalanced` | Per-class selection mode for imbalanced support experiments. |

The selected support set is controlled by `support_seed`, separate from the
runtime seed. For the two class-subset modes `support_seed` chooses *which*
classes are labeled as well as which images inside them, so changing it moves
the experiment to a different class subset. The subsets are not nested across
budgets: a 20% draw is not a superset of the 10% draw at the same seed.

## Unlabeled-Pool Scope

Everything in the training split that the label budget did not select is an
unlabeled candidate by default, including whole classes the labeled support
never covers. `unlabeled_class_scope` chooses between that and a pool restricted
to the support's own classes:

| Scope | Behavior |
|---|---|
| `all` (default) | Every unselected sample is a candidate, unseen classes included. This is the class-mismatch regime. |
| `labeled_classes` | Only the classes the labeled support covers contribute candidates, making the pool in-distribution. |

The scope is read off the labeled positions rather than off the sampling mode,
so it applies uniformly: it is a no-op for `per_class_min`,
`per_class_imbalanced` and a full-coverage `global_budget`, where the two class
sets already coincide, and it bites for `class_subset_k_shot` and a small
`global_budget`. It is rejected for `class_subset`, which labels its selected
classes completely and would therefore leave an empty pool — use
`class_subset_k_shot` to keep a labeled class subset with an unlabeled remainder
inside it.

`unlabeled_fraction` then keeps a share of whatever the scope left. It is
apportioned per class by largest remainder, and successive values nest, so 0.25
is a subset of 0.5 up to per-class rounding and two budgets differ only by the
images the larger pool gained. `max_unlabeled_samples` remains an absolute cap
drawn from the pool as a whole; it is neither class-balanced nor nested, so it
is for bounding cost rather than for sweeping pool size. When several are set
the order is scope, then fraction, then cap.

All three are also CLI arguments — `--unlabeled_class_scope`,
`--unlabeled_fraction`, `--max_unlabeled_samples` — which override the SSL
config file when given and leave it alone when omitted.

## SSL Configs Are For Methods

`--ssl_config` names the SSL method and its `method_params`. It is required by
`--mode ssl` and unused by `--mode supervised`, because the label budget is not
part of it: `--ssl_label_sampling_modes`, `--label_budget_grid` and
`--k_shot_grid` set the budget, and they apply to both modes. A supervised
label-budget baseline therefore needs no SSL config at all, and a config's own
`label_sampling_mode` / `labeled_fraction` / `labeled_per_class` values act only
as fallbacks for grid dimensions the request omits.

`class_subset_k_shot` is the one case where a fallback is refused rather than
guessed: a request that names neither `--k_shot_grid` nor a config
`labeled_per_class` is an error, because the old one-shot default fired exactly
when nothing in the request mentioned k and produced a 1-shot study that read
like whatever k the author assumed.

## Dense Label Mapping

Upstream remaps training labels so classification-style metric losses receive
dense labels starting at zero.

This fork keeps that idea but applies it across more dataset views:

- original provider class IDs are retained for manifests and analysis;
- dense mapped labels are exposed to `MPerClassSampler`;
- pseudo-labeled samples are mapped through the same training label mapper;
- split manifests record the exact selected positions and labels.

## Sampler Capacity Checks

Upstream constructs `MPerClassSampler` directly.

This fork validates label capacity before training. It raises
`MPerClassSamplerCapacityError` when a label-budgeted dataset cannot fill a
valid `batch_size` and `sampler_m` combination. HPO search spaces can also be
filtered against the selected label budget so impossible sampler choices do not
consume trials.

The epoch length can be controlled with `length_before_new_iter`; otherwise it
is derived from the active training dataset size. See
[Sampler epoch length](../length_before_new_iter.md).

## Split Introspection

The fork adds analysis tooling for split validation:

- `class_distribution_report.py` writes distribution tables, overlap reports,
  and charts.
- `check_label_budget_classes.py` compares selected support classes across
  seeds and budgets.
- `check_cifar100_cv_superclass_coverage.py` audits CIFAR-100 superclass
  coverage under fold builders.
- `check_seed_distributions.py` inspects seed-dependent CIFAR superclass
  distributions.

These tools exist because label-budgeted and class-disjoint protocols are easy
to get subtly wrong without explicit split audits.
